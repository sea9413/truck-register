# 装货登记小工具

一个手机上的装货登记工具，支持粘贴司机发来的信息自动识别，数据保存在云端，所有同事打开同一个网址就能一起用。

## 在线地址

https://sea9413.github.io/truck-register/

## 功能

- 📋 粘贴司机信息自动识别（日期、车牌、姓名、身份证、手机号、地址、货物、运费）
- 📍 装货地 / 收货地可下拉选择地点库标准名，司机各种写法自动统一成一个名；没收录的写法可当场「记为新标准名 / 挂为别名」一键入库（v1.8.3 / 1.8.4）
- 📊 统计：六个维度 —— 装货地 / 收货地 / 装+收 / 客户 / 供货商 / 存货量，点一行只看该地点，可复制报表发群（v1.8.4 / 1.9.0 / 1.11.0）
- 👤 客户与供货商由地点派生，不用单独填：送货时收货地=客户、装货地=供货商；退货时反过来（货从客户工地拉回）。客户维度下分「送 / 退 / 净吨」统计（v1.9.0）
- 📦 真实存货量（v1.11.0 / v1.11.1）：「📊 统计 → 存货量」按供货商算 **自有仓库实物（= 初始库存 + 退货 − 送货）** 与 **在客户处存货（= 送货 − 退货）**，两者守恒、调拨不计入（不会虚增供应商库存）；初始库存点单元格直接填，存云端需在 Supabase 跑 `database.sql` 的【第 11 块】。v1.11.1 起点「按货物拆分」可按 盘扣/套扣 等货物看各自的送/退/在客存货（初始库存只按供货商记，故 自有仓库实物/总存货/守恒 仍在供货商汇总行）
- 📦 每车产品明细（v1.12.0 ~ v1.12.2）：登记/修改时可逐规格登记车上装的 **盘扣/套扣** 产品（立杆/横杆/斜拉杆/顶托/底座…），选规格自动带出单重（标准与「脚手架重量计算器」一致，存于 `product_specs` 表，需在 Supabase 跑 `database.sql` 的【第 12 块】），数量×单重=小计；明细合计与「过磅重量」实时对账，差值超阈值标黄⚠️（不阻断保存）。明细存 `record_items` 表（【第 13 块】），详情页展示，一套车可拆多种规格。**v1.12.1 增强**：明细是**可选增强**——没时间填也能只登记车辆+重量、按以前方式统计，后期在详情页点「📦 明细」**只改明细、不动车辆/过磅信息**补登；详情页直接显示「估算 vs 过磅」差值；列表用「待补明细」徽章捡漏（有重量但无明细时提示）。**v1.12.2 增强**：产品明细的规格录入**始终使用两级下拉选择**（部件类型 → 规格型号，和计算器一致），不再因未选盘扣/套扣而回退到自由文本输入；规格表有数据就出下拉，体验统一。两种登记顺序都支持：先登车信息后填明细，或先用明细估算重量、后补车信息与过磅
- 🏷 一个供货商有多个发货点（或客户有多个工地）时，在「📍 地点库」给这几个地点填同一个归属名，统计会合并成一行（v1.9.1，需先在 Supabase 跑 `database.sql` 的【第 9 块】；不跑也不影响其他功能）
- 🚫 归属名是**下拉选择**，选项来自可维护的「🏷️ 名称表」，从清单里选就不会出现「一个供货商两个名字」；已经写错的两种写法可用**改名**合并，正在用旧名字的地点会一起改过来（v1.10.0，需跑【第 10 块】；不跑也能用，下拉会自动收集已经在用的名字）
- 📱 手机浏览器直接打开，无需安装 App
- ☁️ 数据云端同步，所有同事共享
- 📤 一键复制通知文字，发微信群

## 使用步骤

1. 打开网址
2. 点「+ 新增登记」
3. 把司机发来的信息粘贴到识别框，点「识别」
4. 核对自动填入的内容，补填没识别的
5. 点「提交」
6. 点「复制通知文字」，去微信群粘贴发送

## 数据库升级

改过 `database.sql` 之后，到 Supabase → SQL Editor 把**整段**重新执行一次即可。它补齐了这些列，以及被遗漏的权限：

| 补的内容 | 不补会怎样 |
| --- | --- |
| `delivery_type` / `note` / `is_paid` / `modified_fields` / `modified_count` / `deleted` / `deleted_at` | 类型筛选、支付状态、修改标红、回收站全部失效 |
| UPDATE / DELETE 的 RLS 策略 | **修改记录、删除、回收站恢复、清空全部都会失败**（只有 SELECT + INSERT 时数据库会静默拒绝写操作） |

整段脚本可重复执行：已存在的列、索引、策略都会自动跳过，不影响已有数据。

【第 9 块】是可选的：只有需要「一个供货商/客户对应多个地点」时才跑；不跑的话，客户名和供货商名就等于地点名，其余功能照常。
【第 10 块】也是可选的：只有需要「预先维护供货商 / 客户名单、防止同一家被写成两个名字」时才跑；不跑的话，归属下拉会自动把已经在用的名字收进候选（多设备都能看到），只是没法预先登记新名字，改名 / 删除也只在本机生效。

【第 11 块】也是可选的：只有需要「在页面里填供货商初始库存、看真实存货量」时才跑；不跑的话，「存货量」维度里初始库存那格改不了（会提示去跑这块），默认按 0 算，自有仓库实物会相应偏低。

> 第 9 块、第 10 块跑完，各自的验收查询都应该返回 1 行：`rls_enabled = true`、`policy_count = 4`。
> 如果页面上填归属时提示「归属表没读到」，先在「📍 地点库」点一次**重新拉取**（或刷新页面）——
> 页面为了不刷屏报错，会把「表不存在」记在内存里，表建好后不会再自动重试。

## 安全说明

前端的密码门只能防随手访问，不是真正的鉴权 —— anon key 和 RLS 策略都在前端源码里，任何人拿到都能读写数据。因此：

- 身份证号在写库前用登录密码派生的 AES-GCM 密钥加密，数据库里只有密文
- **改登录密码前**，必须先在浏览器控制台执行 `await reEncryptIdCards('旧密码','新密码')`，否则历史身份证号将永久无法解密
- `database.sql` 里的固定盐 `PBKDF2_SALT` 一经发布不可修改，否则所有旧密文失效
- 导出的 CSV 里身份证号是**明文**（为了能重新导入），备份文件要妥善保存
